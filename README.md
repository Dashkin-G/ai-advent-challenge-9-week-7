# AI Advent Challenge · неделя 7 — ассистент разработчика

## День 31. Ассистент разработчика

Ассистент отвечает на вопросы о проекте [ml-student-dropout](../ml-student-dropout) — сервисе прогноза
отчисления студентов. Команда `/help <вопрос>`: ассистент берёт у git текущую ветку и изменения через
**MCP**, находит нужные места в **README и docs/** через **RAG** и отвечает со ссылками на файлы.
Всё работает на этом компьютере: модели **qwen3.5:4b** и **bge-m3** — в Ollama, интернет не нужен.

### Как работает

```
/help где считаются причины риска?
  │
  ├─ ① контекст проекта — MCP-сервер git (в этом же приложении, /mcp/git/)
  │     git_branch · git_status · list_files, а если вопрос про изменения — ещё git_diff
  │
  ├─ ② документация — RAG по README.md и docs/*.md проекта
  │     фрагменты по заголовкам Markdown (78 штук) → векторы bge-m3 → 3 ближайших по смыслу
  │
  └─ ③ ответ — qwen3.5:4b: «контекст git + вопрос + фрагменты + вопрос»
        → ответ со ссылками вида [docs/model.md › Причины риска]
```

- **MCP вызывает код, а не модель**: на каждый `/help` — одна сессия MCP и три-четыре инструмента по
  очереди. Так ответ предсказуем, а на экране виден каждый вызов с аргументами и результатом.
- **Фрагмент — раздел документа**: Markdown режется по заголовкам `#`–`###`; длинный раздел — по
  абзацам до 900 знаков, у таблицы в каждой части повторяется шапка, блок кода не режется. Заголовок
  фрагмента — готовая ссылка для ответа: `файл › раздел`.
- **Индекс обновляется сам**: поменяли документацию — при следующем вопросе пересчитываются векторы
  только изменившихся фрагментов (кэш — `data/embeddings.json`).
- Параметры модели — из дня 29 недели 6: `temperature 0.1`, без штрафа за повторы, ответ до 512
  токенов, контекст 4 096.

### Запуск

1. Ollama запущен, модели скачаны: `ollama pull qwen3.5:4b`, `ollama pull bge-m3`.
2. Проект ml-student-dropout лежит рядом, в `../ml-student-dropout` (другой путь — переменная `PROJECT_DIR`).
3. `pip install -r requirements.txt`
4. `python -m app.main` → http://127.0.0.1:8001 (8000 оставлен самому ML-проекту; другой порт — `PORT`).

При старте приложение считает векторы документации и загружает модель в память, чтобы первый
вопрос не ждал.

### Как проверить задание

- **README и docs/ в RAG** — шаг ② показывает найденные фрагменты: файл, раздел и косинусную
  близость; щелчок раскрывает текст. В шапке шага — сколько файлов и фрагментов в индексе.
- **MCP — git-ветка** — в шапке страницы «ветка main», в шаге ① — ветка, последний коммит,
  незакоммиченные изменения и число файлов. «Вызовы MCP» раскрывают каждый вызов: инструмент,
  аргументы, результат JSON, время. Сервер отвечает по протоколу MCP 2026-07-28.
- **`/help` отвечает о структуре проекта** — примеры под полем ввода; ответ ссылается на файлы
  документации, ссылка подсвечивает фрагмент в шаге ②.

Проверить MCP без страницы — любым MCP-клиентом по адресу `http://127.0.0.1:8001/mcp/git/`.

- Повтор того же вопроса Ollama берёт из кэша: промпт «читается» за 0,1 с, ответ — за 7 с.

### Находки

- **Промах поиска лечится документацией.** На «какие эндпоинты есть в API?» поиск сначала принёс
  описание модулей — в таблице эндпоинтов не было самого слова «эндпоинт», — и модель придумала
  `/dataset` и `/train`. Строка «Эндпоинты сервиса — 12 штук…» над таблицей подняла её с 4-го места на
  1-е (близость 0,55 → 0,70), ответ стал верным.
- **Модели нужен разобранный контекст git.** Списком «файл (статус)» модель увидела только правку
  `.gitignore` из diff и пропустила 22 новых файла. Группы «изменены (1): …; новые (22): …» — и ответ
  полный.
- **Начало промпта не кэшируется.** В Ollama 0.40 у qwen3.5 только 8 слоёв из 32 с кэшем внимания,
  остальные хранят состояние, и общий префикс разных вопросов заново читается целиком. Кэш
  срабатывает лишь на точный повтор промпта. Дату коммита ассистент всё равно передаёт точную, а не
  «5 минут назад», — иначе контекст менялся бы каждую минуту.
- **MCP SDK 2.3**: клиент сначала пробует новый протокол 2026-07-28 (`server/discover`) и
  откатывается на старое рукопожатие. Ошибку инструмента клиент видит своими словами, только если
  сервер бросает `ToolError`; любое другое исключение SDK прячет за «Error executing tool».

### Как устроено

```
app/config.py     проект (PROJECT_DIR), адрес Ollama, модели, порт, сколько фрагментов брать
app/git_mcp.py    MCP-сервер git: git_branch, git_status, list_files, git_diff — только чтение
app/rag.py        документация → фрагменты по заголовкам → векторы bge-m3 (кэш на диске) → поиск
app/llm.py        Ollama: векторы, загрузка модели, ответ потоком со счётчиками
app/assistant.py  /help: вызовы MCP → поиск → промпт → ответ; события для страницы
app/main.py       FastAPI: страница, /api/status, /api/help (поток строк JSON), MCP на /mcp/git
static/index.html страница: поле /help, шаги ① ② ③
```

API: `GET /api/status` — проект и ветка (через MCP), Ollama и модели, индекс документации;
`POST /api/help {"text": "/help вопрос"}` — поток строк JSON: `question` → `mcp` (вызовы и время) →
`sources` (фрагменты) → `prompt` (что ушло модели) → `text`… → `done` (токены, чтение промпта,
генерация) или `error` с номером шага. Текст без `/help` — 400.
